## 已核验的来源行为

- CS 总 RSS 最多返回 2,000 条，未提供分页接口。分页采集应使用官方 `https://arxiv.org/list/cs/new` 页面及其 `skip` / `show` 分页链接。
- 公告页包含日期、全批次条目总数、new / cross / replacement 分节及论文摘要；分页后的总数、条目唯一性和公告日期需要一致。
- `/new` 的含义是最新公告批次。上游没有新的公告日时，页面可能继续显示上一批；抓取时间不能代替页面公告日期。
- 27 日保存的原始页面有 2,443 条公告，两页分别 2,000 和 443 条，包含 1,404 条 new。new 的 ID 集合与当日保存的总 RSS 完全一致。
- 总 RSS 的 `pubDate` 使用当前美东日历日期生成，不能独立证明当日公告已完成。旧公告页加上当天空 RSS，仍可能表示正常停更或上游尚未完成更新。

一手来源：[官方 RSS 说明](https://info.arxiv.org/help/rss.html)、[官方公告查询实现](https://github.com/arXiv/arxiv-browse/blob/develop/browse/services/database/listings.py)、[分页与页面校验实现](https://github.com/arXiv/arxiv-browse/blob/develop/browse/controllers/list_page/__init__.py)、[RSS 日期实现](https://github.com/arXiv/arxiv-feed/blob/develop/feed/utils.py)、[RSS 序列化](https://github.com/arXiv/arxiv-feed/blob/develop/feed/serializers/serializer.py)。

## 官方接口与历史去重的能力边界

- RSS / Atom 订阅由 arXiv 官方维护。公开路由没有按任意日期回查或分页的参数；日期窗口是服务端配置，不是客户端传入的时间范围。需要可靠保存历史批次时，应保留采集到的来源快照。
- 官方 Search API 提供 `search_query`、`id_list`、`start` 和 `max_results`；文档支持 `submittedDate` 日期范围。`published` 是第一版提交时间，`updated` 是所取版本的提交时间。公开接口没有等价于“某公告日的 new 清单”的时间与类型筛选。
- 官方 OAI-PMH 支持批量或增量同步，`from` / `until` 对应元数据记录的变更时间，不是首次公告日期，也可能包含行政或书目信息修订。
- 网站跨日是否已经收录某篇论文，需要自己的归档记录。历史 ID 检查可以发现重复；它不能证明一个从未收录的旧条目属于今天。公告日期、新论文分节和分页完整性仍需要分别核验。
- 用户已确认由本站执行去重，并提议只检查最近 7 天。采纳这个有界窗口；它是当日公告日期与 `new` 类型校验之外的重复保护，不承诺发现所有跨周重复。

一手来源：[RSS 路由](https://github.com/arXiv/arxiv-feed/blob/develop/feed/routes.py)、[Search API 手册](https://info.arxiv.org/help/api/user-manual.html)、[OAI-PMH 日期说明](https://info.arxiv.org/help/oa/index.html#datestamps)。

## 决策树

### 数据完整性与日期

CS 总区分页取得公告内容。逐页校验公告日期、分节计数、连续序号和唯一 ID，完成后复核首页；页间批次变化、解析失败或数量不符时有限重试，失败不得发布部分结果。

分区采集不再作为回退。保留最新公告页的真实日期；旧批次不能改记到今天。

### 去重执行位置

逻辑放在 Python 采集器，Actions 调用采集器执行。首次采集先取得完整的当日 CS 公告，核对日期、new 分节和分页完整性，再做专题筛选与历史去重，最后才翻译、打标签和写归档。

部分专题候选已经收录时，移除这些重复条目并记录数量，继续处理其余论文。历史 ID 集合只来自目标日期 D 之前的七个自然日，即 `[D-7, D-1]`，包含周末，不包含当天，也不向前凑足七份非空日报。同日重跑继续复用已有归档、成功译文和标签。

Actions checkout 的 `main` 当前文件快照中已包含 `data/arxiv-daily/YYYY-MM-DD.json`。直接构造这七个日期对应的文件名，读取存在的有效归档并提取论文基础 ID，无需遍历全部历史或再次从 OSS 下载。不要求尚未建站或没有成功归档的日期一定存在；已存在但损坏的窗口内归档应报错，不静默跳过。以 2026-10-28 为例，窗口为 10 月 21 日至 27 日。

七天窗口限制的是去重读取与 ID 集合的规模，不改变既有 Git 备份保留策略。当前 checkout 仍会取得最新提交内所有受追踪的日报文件；浅克隆不会移除最新提交里的历史日期文件。今后如需限制仓库和 checkout 体积，需单独调整备份保留或检出方式，本轮不删除历史归档。

Actions 的 collect 步骤直接使用采集器退出码；返回非零时，依赖 collect 成功的 publish 作业不会运行。沿用 ECS 的有限重试，每日最多触发 3 次。

### 完全重复与空结果：Q3 结论

用户明确指出周末不发布属于正常情况，不能让 Actions 失败。修订方案如下，不比较含抓取时间和译文的整份 JSON 字节：

| 情形 | 处理规则 |
| --- | --- |
| 北京时间周六或周日，按正常排期不发布新论文 | 成功生成、发布零篇日报，记录周末排期依据；ECS 认定当天完成，不再重试 |
| 非周末目标日期，来源仍是旧公告批次 | collect 失败，不生成当日归档，等待有限重试 |
| 非周末来源为空、没有可验证的公告内容、分页或解析失败 | collect 失败，不把未知结果记为零篇 |
| 当日专题候选非空，但去重后全部已在前七天日报中收录 | collect 失败，记录没有新的可发布论文 |
| 仅部分专题候选重复 | 移除重复，继续处理剩余论文 |
| 完整有效的当日公告有论文，但 new / 关键词筛选后无命中 | 成功归档零篇 |
| 同一日报日期的正常重跑，已有归档没有新增论文 | 复用归档并补失败译文或标签；不因相同集合判失败 |

周末以北京时间判断，可在请求来源和模型前直接按排期生成零篇结果。公共数据约定应明确区分“周末排期零篇”和“当日公告筛选后零篇”，不能伪造上游当日空批次或公告更新时间。已有归档的普通重跑继续遵循复用规则。

上述方案不依赖 RSS 判空，也不额外维护节假日日历。非周末遇到停更、延迟或其他原因导致没有当日有效批次，仍按未取得结果处理并有限重试，页面保留“日报尚未更新”。周末正常结束、零篇发布及其余配套行为构成本轮修订结论。

正常周末对应关系依据：[arXiv 官方公告排期](https://info.arxiv.org/help/availability.html#announcement-schedule)。美国东部周五、周六晚上没有公告，对应北京时间周六、周日早晨。

## 实现前验收范围

- 超过一页和超过 2,000 条的总区公告能完整获取；全过程不请求子分类 RSS。
- 跨页分节正确，只从 new 条目构建候选；在完整性检查成功后再执行专题筛选和模型请求。
- 跨页重复、缺页、计数变化、旧日期及请求失败不会产生错误的当日结果。
- 历史去重仅读取目标日期前七个自然日的归档，按论文基础 ID 识别版本；不读取更早日期，不向前凑足七份非空日报，部分重复能够剔除，同日重跑不会把自身视为历史重复。
- 北京时间周六、周日正常生成零篇结果，不调用翻译与打标；零篇发布完成后 ECS 不重复触发。日期判断不受运行器本地时区影响。
- 非周末的旧日期、空响应或抓取故障仍失败；完整当日来源仅因专题筛选无命中时成功归档零篇。
- 既有成功译文和有效标签的普通重跑复用行为继续符合现有规格；新方案只影响后续首次采集。

没有新的业务选择需要澄清。进入实现后更新 `docs/spec.md`、`docs/collector.md` 和公共数据约定，并按以上范围实施、验证；分页解析和公共数据兼容等技术细节在实现中解决。

新数据继续使用 `schemaVersion: 1`，新增来源类型，同时兼容不含 `source.kind` 的旧 RSS 归档：

- 公告页来源：`source.kind = "cs-announcement-list"`，`url` 为总区 `/list/cs/new`，`announcementDate` 为页面明确给出的日期并等于日报日期，`updatedAt = null`。`source.counts` 为 `total`、`new`、`cross`、`replace` 四个非负整数，三种分节之和等于总数且总数非零。`stats.fetched` 等于来源总数。
- 公告页没有提供精确的提交或更新时间，新条目的 `publishedAt`、`updatedAt` 使用 `null`；不额外逐篇请求 API，不伪造时间戳。分类、主分类和原文链接按页面提供的信息保存，保留来源实际给出的 ID，不擅自补 `v1`。
- 周末来源：`source.kind = "announcement-schedule"`，`url` 指向官方公告排期，`reason = "weekend"`，`updatedAt = null`。仅允许北京时间周六、周日，论文和四项既有统计均为零。此类型不声称取得了当天空公告。
- 新公告页或排期归档增加 `stats.duplicates`，为翻译前剔除的前七天重复候选数；排期归档为零。旧归档可以没有此字段，同日重跑保留原来源及已记录的去重统计。
- 新来源元数据同时通过 Python 发布校验和页面读取边界验证；旧归档继续可读。正常零篇页面沿用现有交互，无额外来源提示。
- 来源覆盖配置改为 `ARXIV_LIST_URL`，默认 `https://arxiv.org/list/cs/new`；不再通过环境变量提供 RSS 采集模式。分页参数由采集器构造，使用上游支持的分页大小，并对整个批次有限重试。
